## 三、项目类型

本项目是使用 MoonBit 原创实现的开发者工具库，提供核心库、命令行工具、
可运行示例、自动化测试、持续集成配置和申报材料。项目采用 Apache-2.0
许可证，不依赖外部运行时包。

## 四、项目背景与问题

许多服务、构建系统和命令行工具会输出如下形式的 logfmt 日志：

```text
level=info msg="service ready" request_id=req-42
```

这种格式便于人工阅读，也容易由程序生成，但实际使用中存在多类容易被忽视的
质量和安全风险：

- 重复键可能让后一个值覆盖前一个值，造成语义歧义。
- 缺失 `level`、`msg`、`service` 等关键字段会破坏下游查询。
- 字段可能在不同版本之间从整数悄然变成文本。
- 新增字段可能意外泄露访问令牌、邮箱、手机号或支付信息。
- 日志结构种类持续增长时，监控查询和索引成本会失控。
- 新版本日志与已验证基线发生漂移后，通常缺少可解释的差异报告。

MoonBit 生态已经存在日志输出和可观测性相关项目，但仍需要一个专门消费
logfmt 文本、并将解析、契约、脱敏、批量画像和漂移检测连成闭环的工具。

## 五、项目目标

MoonLogfmt Lens 主要解决以下问题：

1. 判断一条 logfmt 记录是否合法、是否存在歧义。
2. 判断记录是否符合可执行的字段契约。
3. 在日志进入 CI、支持工单或下游系统前识别并隐藏敏感信息。
4. 从一批已知日志中推断字段类型、出现率和候选契约。
5. 使用不包含具体值的结构指纹比较不同批次。
6. 解释新版本相对于已知良好基线发生了哪些实质变化。

## 六、已完成的功能

当前版本为 `0.2.0`，已完成以下内容：

### 1. logfmt 解析与基础审计

- 支持裸值、引号值、常见转义、显式空值和 flag 字段。
- 保留字段顺序、原始偏移和部分解析结果。
- 检测非法键、意外等号、裸引号和未闭合引号。
- 检测重复键、必填键缺失、空值、超长值、字段过多和控制字符。
- 提供默认、CI 和宽松三类审计策略。
- 输出文本报告和 JSON 报告。

### 2. 语义值分类

提供统一、确定性的值类型分类器，可识别：

- flag、空值、布尔值；
- 整数、小数、时长、字节大小；
- 时间戳、IPv4、UUID、邮箱；
- 十六进制值、标识符和自由文本。

该分类体系同时服务于契约验证、Schema 推断、批量画像和漂移分析，避免不同
模块各自采用不一致的判断标准。

### 3. 可执行日志契约

- 支持必填字段和可选字段。
- 支持语义类型、最大长度和受控取值集合。
- 可分别控制空值与 flag 字段。
- 可设置记录最大字段数。
- 对未知字段提供允许、警告和拒绝三种策略。
- 对语法错误、重复字段、类型不符和取值越界生成可解释报告。
- 内置服务日志契约和 CI 事件契约。

### 4. Schema 自动推断

- 统计字段出现率、值数量和最大长度。
- 统计每种语义类型的分布。
- 计算主导类型和类型置信度。
- 有界收集不同取值，避免无上限保存样本。
- 根据样本生成候选 `LogContract`。
- 仅对 `level`、`environment`、`state`、`outcome` 等明确分类字段推断枚举，
  避免把普通消息误冻结为有限集合。

### 5. 隐私扫描与脱敏

- 基于字段名识别密码、令牌、授权头、Cookie、会话、邮箱、手机号、
  支付字段和网络身份。
- 基于字段值识别 Bearer 凭据、常见访问密钥前缀、三段式令牌、
  私钥标记、邮箱、格式化手机号、通过校验和的支付卡号及高熵字符串。
- 严格策略可将 IP 地址作为敏感信息处理。
- 支持完全遮盖、仅保留后四位和稳定令牌三种模式。
- 支持显式允许列表，降低可控场景中的误报。
- 文本与 JSON 报告均不输出原始敏感值。

### 6. 批量画像与质量门禁

- 统计有效、无效、低风险、中风险和高风险记录。
- 计算无效率、高风险率、平均风险分和总风险分。
- 生成字段画像和结构聚类。
- 结构模板只保留键名和语义类型，不保留具体值。
- 结构指纹不受字段排列顺序影响。
- 可限制不同结构数量，防止日志结构基数失控。
- CI 门禁支持无效率预算、高风险预算、平均风险预算和必填字段出现率。

### 7. 基线漂移检测

- 检测新增字段和消失字段。
- 检测主导语义类型变化。
- 检测类型置信度下降。
- 检测字段出现率明显上升或下降。
- 检测最大值长度增长。
- 检测新增结构和退役结构。
- 检测无效率和平均风险回归。
- 可将已验证批次冻结为后续版本使用的可执行契约。

## 七、创新点

本项目不是日志生成器，也不是遥测采集器。其创新点是形成完整的消费侧治理
闭环：

```text
logfmt 文本
  -> 解析与语法审计
  -> 语义类型画像
  -> 候选契约推断
  -> 隐私安全投影
  -> 无值结构指纹
  -> 新旧批次漂移解释
```

解析结果并未停留在“能读出键值”的层面，而是成为契约、脱敏、批量门禁和
版本漂移分析共同使用的证据。结构指纹不保存具体日志值，使批次比较可以在
降低数据暴露风险的前提下进行。

## 八、技术路线与可行性

核心解析器使用 MoonBit `Char` 数组实现手写扫描，不依赖解析器生成器。
各模块通过公开结构体和枚举组合，避免绑定文件系统、网络或特定运行环境。

当前格式化后的 MoonBit 手写代码共 5558 行，分布如下：

- 核心库：4410 行。
- 自动化测试：976 行。
- CLI 与示例：172 行。

项目包含 16 个 `.mbt` 文件、五种 CLI 模式和四个可运行示例。全部核心能力
均已有实际实现和测试，不依靠重复代码或空接口凑行数。

## 十一、应用价值

- MoonBit 包作者可用它验证示例和构建日志。
- CI 系统可用它阻止日志格式回归。
- 服务团队可用它冻结日志契约并审查版本漂移。
- 支持和运维工具可先脱敏，再生成诊断材料。
- 日志平台接入方可在正式采集前发现字段不稳定和结构基数增长。

## 十三、项目边界

本项目不负责日志采集、文件跟踪、网络传输、OpenTelemetry 导出、JSON 解析
或应用运行时日志输出。隐私检测采用可解释启发式规则，稳定令牌和结构指纹
不声明具备密码学安全性。高安全场景仍需结合密钥管理、访问控制和专用数据
防泄漏系统。
